# 보관 정리와 결과 고정

기본 보관 기간은 완료 뒤 30일이다. 서버가 실행 중일 때 하루에 한 번, 업무 실행 슬롯과 겹치지 않게 최대 100개 업무와 500개 삭제 대기 파일을 처리한다. 검사 위치를 저장해 다음 날 이어서 검사하고 끝에 도달하면 처음으로 돌아간다. 보호되거나 잠긴 항목이 앞에 많아도 뒤의 항목을 계속 검사한다. 원본 자료와 기억은 자동 삭제하지 않는다.

결과의 **계속 보관** 버튼은 그 파일과 해당 업무를 고정한다. 고정을 해제하면 다음 정리 때 30일 기준을 다시 적용한다. `POST /api/artifacts/{id}/pin`은 인증된 소유자의 프로젝트 파일에 `{pinned:true|false}`만 받는다. 고정된 파일의 ID·SHA256은 서버에 보관한다.

다음 자료는 기한이 지나도 보존한다.

- 고정 결과와 다른 업무·기억·현재 자동화 상태가 참조하는 결과
- 승인 대기, 미정산 호출, 사용량 미상, 미전송 또는 전달 여부가 미상인 결과
- 입력·승인·실행을 기다리는 업무와 원본 자료

정리 시 요청·계획·단계 출력·완료 문서 내용을 지운다. 같은 요청이나 사건이 다시 실행되지 않도록 run ID·요청 hash·사건 식별 기록과 전달 식별 기록은 유지한다. 호출 계측값도 유지해 월 사용량을 줄여 보이지 않는다. 화면에는 보관 기간이 지난 업무로 표시한다.

DB에서 참조와 대기 상태를 확인하고 tombstone을 저장한 뒤 관리 `drafts`·`exports`의 정확한 파일만 지운다. 파일 경로/해시가 달라졌거나 잠겨 있으면 원래 파일을 지우지 않고 삭제 대기로 남긴다. 파일을 지운 뒤 DB 기록이 실패하면 다음 실행이 이를 수복한다. 원본 경로나 하위 폴더를 재귀 삭제하지 않는다.

백업·복구는 [OPERATIONS.md](OPERATIONS.md)를 따른다. 관리 파일 삭제는 정리 함수가 수행하며, 백업에서 기록이 있는 파일이 없다는 이유만으로 정상 원본 누락을 묵인하지 않는다. 삭제 완료 또는 삭제 진행 중 tombstone은 따로 대조한다.

기억의 **삭제**는 검색에서만 제외한다. **원문도 제거**는 별도 확인 후 그 기억의 모든 저장 버전 파일까지 제거한다. 진행 중인 참조가 있으면 즉시 검색에서 제외하고 파일 제거 요청을 DB에 보관한다. 서버의 다음 일일 정리에서 참조 해제를 다시 확인한다. 한 번에 최대 50개 요청을 확인하며 잠긴 요청은 다음 검사로 넘긴다. 재시작 후에도 명시적인 제거 요청을 이어서 처리한다. 참고한 업무 자료 원본은 이 요청에 포함되지 않는다.

검증: [test_retention.py](../tests/test_retention.py), [test_runtime.py](../tests/test_runtime.py). 실제 파일·SQLite를 사용했고 Office parser와 외부 API는 이 경계 검사에 사용하지 않았다.
